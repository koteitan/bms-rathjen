## 記号: `E.` / `P.` / `D.` と、この文書の設計ラベル

**別の階層の語彙なので混同しないこと。**

| | 何を指すか | どこにあるか |
|---|---|---|
| `E.` / `P.` / `D.` | 表の行が満たす命題・補助命題・定義。名前は Lean の識別子 | [../table/table-r1.md](../table/table-r1.md) の「エビデンス」節 |
| E1 / E2 / E3 / G / MT | **行ごとに何を証明しにいくか**という設計上の分類 | この文書 (下記) |

`E.` などは**結果**の名前で、E1 などは**作業**の名前である。表の主張は前者だけで
構成され、後者は表に現れない。

`D.Certified` の `lim` 節は前提を 5 つ取り、そのうち**同一性を述べるのは 1 つ**、
残る 4 つは基本列 `fs'` の性質である:

```
kind M = lim                                  行列が極限であること
∀ n, Certified (expand M n) (fs' n)           ← 同一性。列を一意に固定する唯一の前提
∀ n, lt (fs' n) t                             \
∀ n, lt (fs' n) (fs' (n+1))                    |  性質。lim_clauses_* が束ねて供給する
∀ s, inT s → lt s t → ∃ n, le s (fs' n)       /
```

**性質をいくつ検査しても選択は固定されない** ([constitutions.md](constitutions.md) C2)。
較正事故はここを取り違えて起きた。

## エビデンスの設計(何を証明するか)

整礎性(整列性)の証明は要求せず、「基本列付き表記系としての対応」を証明対象とする。
以下の対象はすべて構文的に定義され、順序・述語は決定可能である
(Lean 上ではここに書いた数式と 1:1 に対応する定義・定理を置く)。

**BMS 側**

- 行列の集合 $`\mathcal{M}`$ と辞書式順序 $`\lt_B`$
- 展開 $`M[n]`$ ($`n`$ 番目の展開。活性化関数の任意化)
- 標準形述語 $`\mathrm{Std}(M)`$ (初期行列からの展開到達性)

**$`T(M)`$ 側** (Rathjen 1991 の構文的定義に忠実)

- 項の集合 $`T`$、項の順序 $`\lt_T`$、正規形述語 $`\mathrm{NF}`$
- 基本列 $`t[n]`$ (本リポジトリで一様に明示定義する)

**翻訳関数** $`o\colon \mathcal{M}\to T`$ (= 対応表の一般化・一様化)

証明する命題は次の 4 群 (E1, E2, E3, G) である。

### E1 (行検査) — 表が単一アルゴリズム $`o`$ の出力であること

表の各行 (行列 $`M_i`$, 項 $`t_i`$) について

```math
o(M_i) = t_i
```

を計算で機械検査する。これ自体は $`o`$ の正しさを主張しない。
「全行が 1 つの $`o`$ から機械的に出た」ことの保証である。

### E3 (展開と基本列の整合) — 本体のエビデンス

添字の規約: BMS の $`M[n]`$ はコピー $`B(0),\dots,B(n)`$ の $`n{+}1`$ 個を並べるため、
$`T(M)`$ 側の基本列とは添字がずれる。**ずれ幅は行ごとに違う。**

この段落は以前「1 ずれる ($`o(M[n])`$ は $`t[n{+}1]`$)」と書いていた。**誤りである。**
9 本の E3 証明で実測すると $`n{+}1`$ が 4 行、$`n{+}2`$ が 1 行、$`n`$ が 2 行
($`\varepsilon_\omega`$ を含む)、残る 2 行は専用の再帰で、どの添字ずらしでも書けない。
**一様に $`+1`$ を当てると 624 中 612 が不一致になり、これは
「$`\varepsilon_0`$ より上で $`\mathfrak{T}(M)`$ の基本列が壊れている」と読める数字だが、
壊れているのは仮定のほうである。** 比較の前に各行の `e3_val` を読むこと。

**実装後の知見**: BMS の展開列と $`T(M)`$ の基本列は、同じ順序数への
**異なる共終列**になり得る (例: $`\varepsilon_1`$ へ BMS は
$`\varepsilon_0, \varepsilon_0^2, \varepsilon_0^{\varepsilon_0}, \dots`$ で登り、
標準的な fs は $`\varepsilon_0{+}1, \omega^{\varepsilon_0+1}, \dots`$ で登る)。
そこで E3 は等式ではなく**相互共終形**で立てる。行ごとに:

```math
\forall n.\ o(M_i[n]) <_T t_i,
\qquad
\forall n\,\exists k.\ o(M_i[n]) <_T t_i[k],
\qquad
\forall k\,\exists n.\ t_i[k] <_T o(M_i[n])
```

($`\exists`$ は行ごとに具体的な witness 関数で与える)。
両側の列が互いに追い越し合えば上限は一致するので、
これで「$`M_i`$ と $`t_i`$ が同じ極限を指す」ことが担保される。
なお CNF 領域 ($`\varepsilon_0`$ 以下) では添字ずれを除いた等式
$`o(M[n]) = o(M)[n{+}1]`$ がそのまま成り立ち、成り立つ領域ではこちらも記録する。

あわせて $`o`$ が零・後続・極限の分類を保つこと
(後続なら $`o(\mathrm{pred}(M)) = \mathrm{pred}(o(M))`$)。

#### この形が ✅ に要るわけではない

**✅ の付く行では、E3 の内容は `Certified` の中で既に言われている。** `Certified.lim` の
第 1 連言は $`f_n`$ が $`M[n]`$ の値そのものであることを要求するので:

| E3 (相互共終形) | `Certified` 側 |
|---|---|
| $`\forall n.\ o(M[n]) \lt_T t`$ | 第 2 連言 $`\forall n.\ f_n \lt t`$ そのもの |
| $`\forall k\,\exists n.\ t[k] \lt_T o(M[n])`$ | 第 4 連言で $`s = t[k]`$ と取れば出る |
| $`\forall n\,\exists k.\ o(M[n]) \lt_T t[k]`$ | 基本列が $`t`$ に共終であることから出る |

**しかも `Certified` 側は $`o`$ に一度も触れない。** E3 は $`o`$ を経由するので、読み手が
誤っていれば道連れになる — 較正事故のあと $`o`$ 抜きの形へ移した理由がこれである。
E3 が担うのは **✅ の無い行**であって、✅ の根拠ではない。

#### なぜ等式で書いてはいけないか — 棄却の向きの問題

**相互共終形は「等式で書くな」という警告そのものである。** 両側が同じ極限へ登るのだから
対応するはずだ、と考えて等式で立てると、不一致が大量に出る。そのとき疑われるのは
**前提ではなく部品のほう**だった:

```
612/624 が不一致
  疑われた    fsN (正しかった)
  疑われない  「両側が対応するはず」という前提 (これが誤り)
```

**測定は前提を疑ってくれない。** 612 という数字は「fsN が壊れている」の証拠にも
「前提が誤り」の証拠にも同じように見える。区別できるのは、正しい形が先に書いてあるときだけ
である。これは C2 の一族だが、C2 が「性質は値を決めない」なのに対し、こちらは
**「不一致は、どちらが悪いかを言わない」**。

逆向きの罠も同じ根から出る。**添字を行ごとに調整して等式を通す**ことはできるが、
合わせ込んだ添字は証拠ではなくデータへの当てはめであり、今度は**誤った値を受理する**側の
失敗になる。相互共終形なら添字が要らないので、どちらの罠にも入らない。

### G (片側ずつの構造定理) — 展開・基本列の単調性と共終性

E 群がすべて翻訳 $`o`$ に言及する「対応の主張」であるのに対し、
G 群 (G = ground, 土台) は $`o`$ に言及しない。BMS・$`T(M)`$ それぞれ単独の性質
(対応表が正しいか否かに依らず各表記系が持つべき土台)なので、
E の番号とは別のラベルにしている。

$`T(M)`$ 側: 極限の正規形項 $`t`$ と任意の $`s\in\mathrm{NF}`$ について

```math
t[n] <_T t,
\qquad
s <_T t \implies \exists n.\ s <_T t[n].
```

BMS 側: 標準形の $`M, N`$ について

```math
M[n] <_B M,
\qquad
N <_B M \implies \exists n.\ N <_B M[n].
```

### E2 (順序埋め込み) — 照合用

標準形の $`M, N`$ について

```math
o(M) \in \mathrm{NF},
\qquad
M <_B N \iff o(M) <_T o(N).
```

順序は決定可能なので、一般定理の完成前でも個別のペアは計算で即検査できる。

### MT (主定理: 条件付き意味論)

「$`\lt_T`$ の $`\mathrm{NF}`$ 上への制限が整礎」という仮定を $`\mathrm{wf}`$ と書く。
E3 + G + (E2 のうち $`o(M)\in\mathrm{NF}`$) から次が従う:
$`\mathrm{wf}`$ のもとで、任意の標準形 $`M`$ について

```math
\mathrm{otype}\bigl(\{\,N \in \mathcal{M} : \mathrm{Std}(N),\ N <_B M \,\},\ <_B\bigr)
\;=\;
\mathrm{otype}\bigl(\{\, s \in \mathrm{NF} : s <_T o(M) \,\},\ <_T\bigr)
```

($`\mathrm{otype}`$ は順序型)。左辺は「行列 $`M`$ の表す順序数」、
右辺は「項 $`o(M)`$ の表す順序数」だから、これは対応表の行の主張そのものである。

証明の骨格: $`M`$ が極限のとき、G の共終性により両側の below 集合が増大和

```math
\{\,N : N <_B M\,\} = \bigcup_n \{\,N : N <_B M[n]\,\},
\qquad
\{\,s : s <_T o(M)\,\} = \bigcup_n \{\,s : s <_T o(M)[n]\,\}
```

になり、E3 の相互共終により両側の増大和が同じ集合を尽くし、
帰納法の仮定で順序型が一致する(零・後続も同様)。
仮定 $`\mathrm{wf}`$ は紙の上では既知(Rathjen 1994 の整列証明)であり、
そこだけを明示的な仮定として切り出す。

### 各群と MT の関係

MT は「E1〜E3 と G を証明したことが、なぜ対応表のエビデンスになるのか」を
1 枚で示す正当化の定理である。依存関係:

```
E3 (展開↔基本列) + G (両側の共終性) + E2 の一部 (o(M) ∈ NF)
        │
        │  wf を仮定した超限帰納法
        v
MT:  otype(M より下の標準形行列) = otype(o(M) より下の正規形項)
        │
        │  E1 (o(M_i) = t_i) を代入
        v
行 i の最終主張: 行列 M_i の表す順序数 = 項 t_i の表す順序数
```

- E3 + G は MT の証明の材料。
- E1 は MT を表の各行に適用するための入口。
- E2 の順序同値は MT の証明には使わない独立のクロスチェック
  ($`o`$ に誤りがあれば MT より先に E2 の計算検査が落ちる、早期検出の役割)。
- 成果物は 2 層に分かれる:
  **無条件の構文的成果物 = E1, E2, E3, G** /
  **条件付き ($`\mathrm{wf}`$ を仮定) の最終主張 = MT**。

### 恣意性の排除と誤り検出

- $`t[n]`$ と $`o`$ は本リポジトリの定義だが、**一様性**(全項・全行列に対する各 1 つの定義が
  全行で同時に E3 を満たすこと)が内容であり、行ごとの調整による偽装は構造上できない。
  $`T(M)`$ の項・順序・正規形は Rathjen の論文で固定されている。
- 表のある行が誤っていれば、E2 の計算検査(順序の逆転)または
  E3 の具体的な $`n`$(基本列の不一致)が反例として機械的に得られる。
  これは失敗ではなく成果(表の訂正)として報告する。

### 注意

- BMS 側の共終性 ($`N \lt_B M \implies \exists n.\ N \lt_B M[n]`$) が G の最難部で、
  一般の BMS では研究課題。まず表の対象範囲の行列クラスに制限して証明する。
- MT の記述のみ順序数型(mathlib)を要するため mathlib 導入後に行う。
  それまでは E1+E2+E3+G が無条件の構文的成果物である。

### 各部の役割と方針

- **BMS/**: 行列は `List (List Nat)`(列のリスト)で表現し、行数は固定しない。
  展開規則は数式的定義に従い、活性化関数は固定せずコピー数 `n : Nat` を
  展開の引数として与える(これにより行列は `[n]` なしの順序数表記として扱える)。
  実装の正しさは [yaBMS](https://github.com/koteitan/yaBMS) の C 実装
  (展開・大小比較・標準形判定)との出力照合 (`scripts/crosscheck.sh`) で担保する。
- **TM/**: 1990 論文の $`T(M)`$ を項システムとして構文化する。
  比較 `<_T` と正規形は論文の定義から決定可能手続きとして書き下す。
  基本列 `FS` は論文に無いため、コミュニティの慣用(UNOCF 等)を参考に明示定義し、
  定義の出典・選択理由をコメントで残す。
- **Trans/**: 対応写像 $`o`$。ここが本プロジェクトの研究部分であり、
  E2/E3 が落ちる場合は $`o`$(または表)の誤りが反例として検出される。

### 一般則: 整合性は決定しない (2026-08-10、Veblen キャンペーンでの発見)

較正事故の教訓の一般形が、証明書の基本列を作る作業で再び現れた。記録しておく。

**共終性は基本列を決定しない。** 同じ項の下で共終な列は多数ある。ε₁ について
3 つの候補 (ε₀+1 から反復 / ε₀ から反復 / fsN の混合) を挙げ、**実測ですべてが**
各添字で CNV・狭義増加・ε₁ 未満・共終であることを確認した。しかし真の列は
**第四のもの**で、行列から読み取るしかなかった (ε₀, ω^(ε₀·2), ω^(ω^(ε₀·2)), …)。

理由は構造的である。`Certified.lim` は

```
∀ n, Certified (BMS.expand M n) (fs' n)
```

を要求するので、`fs'` は選ぶものではなく **n 番目の展開の認証値そのもの**であり、
行列が一意に決めている。𝔗(M) 側の順序から列を導き、共終性を確認する手順は、
**もっともらしい誤答しか生まない**。実際 1 セッションで 2 回それを生んだ。

したがって残りの行はすべて、**先に展開を実測し、閉形式をそこから読む**。

これは較正事故と同じ形である。あのときは「自己整合的だが誤った読み」が
すべての内部検査を通った。今回は「正当だが当該行列のものではない列」が
共終性検査を通った。**ある性質を満たすことの確認は、対象を決定することではない。**

**さらに強い形 (同日中に発見)**: 共終性だけでなく、**`Certified.lim` の 4 条件を
すべて満たしても列は決まらない**。ε_ω の行で、既存の `lim_clauses ω` を再利用すると
列は ε₁, ε₂, ε₃ になる。これは CNV・行より下・狭義増加・共終の 4 条件をすべて
**緑で**通る。しかし行の n 番目の展開の値は ε_n であって ε_{n+1} ではない。
つまり誤りが**どの条件にも現れない**。

列を一意に固定しているのは 4 条件ではなく、`Certified.lim` のもう一つの前提

```
∀ n, Certified (BMS.expand M n) (fs' n)
```

だけである。**4 条件は列の性質を述べており、この前提だけが列の同一性を述べている。**
検査を増やしても決定にはならない、という事実の最も鋭い形。

**実行可能な形** (この規則を「緑を疑え」より狭く、使える形にしたもの): 誘惑が
生じたのは、既存の証人が**すぐそこにあって型が付いた**からである。それを止めた
検査は補題への懐疑ではなく、**「この行の n 番目の展開は実際に何か」を計算して
比べたこと**だった。だから運用上の規則はこう述べるべきである —

> 前提が「`fs' n` は何かと**等しい**」と言っているとき、`fs'` のどんな**性質**も
> その何かを**計算すること**の代わりにはならない。

`Certified.lim` の他の前提はすべて性質であり、この一つだけが同一性である。
**選択を固定できるのは同一性を述べる前提だけ**であり、性質を述べる前提は
何個増えても固定しない。

cert_sound への設計入力 (v0.1.70 検収時の文レベル監査、2026-08-09):

1. 値の一意性が本体: `cert_tower` は各展開の証明書の存在定理であって

   → v0.1.80 で、これより良い形が実装された。証明携行型にする代わりに
   **ゲート自体を強めた**: `certIn_rows_inT` (値がすべて inT である証明書を

### 項 → 行列の写像: TransRev を採らない (2026-08-10 決定)

証明書を ε₀ より上へ伸ばすには「項 → 行列」の写像が要る。オラクル側 (naruyoko 氏の
`common.js`) には逆写像 `TransRev` が実装されており移植は安い (30〜50 行) が、
**証明のためには採らない**。理由は 3 つで、1 つ目が決定的:

1. **循環**。`TransRev` は `Trans(N1) == t` になった時点で `N1` を返す探索である。
   これで行を認証すると、**その行の値を生成したオラクル自身に対して認証する**ことに
   なる。較正事故 (v0.1.41/42) とまったく同じ形。
2. `TransRev` は構文的写像ではなく展開木の探索なので、**展開の等式はその出力ではなく
   入力**である。`sq` の価値は写像であることではなく `sq_decomp` が構文的分解を作る
   ことにあった (それが §10〜§13 を 2 セクションで済ませた理由)。探索の出力の上で
   再帰はできない。
3. 停止性は p 進大好き bot 氏の定理であって移植されていない。JS の fuel 上界は
   文字列長のヒューリスティクスであり、fuel 有界のループからは定理が出ない。

**オラクルとしても不要**: `dictInv` (Term → BT) と `enc` (BT → Matrix) の合成で、
探索も JS も使わない純 Lean の `t2m : Term → Option Matrix` が作れることが実測済み。
`TransRev` が正直にできた唯一の仕事は、これで既に済んでいる。

採るのは**直接定義** (`sq` 方式) で、次の領域は ψ/Z ではなく **Veblen 帯**
(ε₀ 〜 Γ₀)。表の 12 行はすべて φ̄ のみで ψ・Z を含まず、Γ₀ が最初の真の ψ 行である。
第一歩は `sqv : Term → Matrix` を CNV 項の上に 3 節 (zero / 和は連結 / φ̄ab は
a で決まる梯子 + b のシフト符号化) で定義し、**証明を 1 行も書く前に `#eval` で
検査する**こと。検査対象はリポジトリ自身の展開閉包 (`BMS.expand?` から生成した
34789 行列; 合成写像は 34785 一致・4 が既知の `1+` 規約・0 不一致) と表の全行。

なお整礎性の前提は**既に済んでいる**: `acc_cnv` / `acc_inT_below_cnv` が CNV 全体
(= Γ₀ 未満) の到達可能性を最終形の関係で与える。`Certified.lim` は任意の `fs'` を
取るので、展開の値を直接与えればよく `fsN` に合わせる必要もない。

### 整礎性 (wfT → wfB) のロードマップ

**目標の確定 (2026-08-09)**: 整礎性の到達目標は **R1 の最大**、すなわち
$`\psi_{\Omega_1}(\varepsilon_{M+1})`$。Γ₀ 未満 (Veblen 領域) までではない。

**設計原則: 関係は最終形で固定し、述語を層ごとに狭める。**

```
RT x y := inT x ∧ lt x y        関係。最終形。以後変えない
段 1:  ∀ t, CNV t → Acc RT t     Veblen 領域 (Γ₀ 未満)
最終:  ∀ t, inT t → Acc RT t
```

`CNV ⊆ inT` なので段 1 は最終目標の literal な部分主張であり、ψ の段が
来ても述べ直しが発生しない。**述語を先に広げてはならない**: `inT` 上で
述べると内側の補題の生きる形が 3 から 5 に増える (ψ・Z 項は φ̄ 項より下に
実在する、2.3.4)。崩壊領域が段 1 に流れ込み、段階分けが消える。

**段 1 の断片** `CNV` = `Frag` + 2.1(iii) を和にのみ課したもの
(成分が加法主要かつ降下)。Veblen 正規形の条件は不要 — 前置降下は
次数 12 までの完全コーパスで ⊕ に 1,224,175 件、φ̄ に 0 件 (較正済み対照)。
`CNV` は次数 8 で `inT ∩ (< Γ₀)` にちょうど一致することが実測されている。

**永続性の根拠**: `cnv_of_lt_cnv` (inT 順序の下で CNV が下方閉)。これにより
CNV 上の到達可能性が「Γ₀ 未満のすべての真の項の到達可能性」を直ちに与える。

**継ぎ目 (ψ_κ の段で何が生き残らないか)**: φ̄ では `x < φ̄ a b` が x を
**構造的に**縛るので内側補題が構造帰納法になるが、ψ_κ ではそうならない
— それが崩壊の意味である。ここから先は Rathjen 1994 の
distinguished set / C_κ 機構であり、ケースの追加ではなく別手法。
`cnv_of_lt_cnv` の ψ 版は**おそらく偽**である (ψ_κ α の下には任意の形の
項が来る) ため、この永続性の技法自体は Veblen 層固有の贈り物と見るべき。

**分割の可否**: この道では**全段でファンアウトしない**。段 1 は 10〜14
ケースで分割の間接費が証明を上回り、ψ/Z 段はケースが独立でない。
(§8.4 形式の分割は Stage 3b では正しかったが、ここでは誤り。)

**移送経路について**: 「Buchholz 辞書で pss-proof の整礎性を移送」は
現状では補題ではなく**インフラの判断**である。`lake-manifest.json` に
外部依存はゼロで、`lean/` から pss-proof を import しているものは無い。
加えて `Dict.lean` の `BT.lt` は本リポジトリ自身の転記なので、`dict` の
順序保存性を証明しても、それを pss-proof の証明済み関係と同一視する
第二の主張が別に要る。辞書はオラクル照合装置として優秀だが、
整礎性の移送手段としては現状不適。

### Buchholz → 𝔗(M) の差し替え候補を測って却下した (2026-08-12)

`Trans.Dict.dict` はアンカー `(0,0)(1,1)(2,2)` で外部資料 2 つと食い違う。そこで
「先頭の高添字ブロックを一段下で崩す」設計の候補を作らせ、資料の値に合わせた。
候補は資料の 200 行に 200/200 で一致した。**それでも採らない。**

理由は 1 つで、測って初めて出た。訂正後の標準形コーパス (3193 項、順序対 5096028) で:

| | inT の外 | 順序反転 | 衝突 |
|---|---:|---:|---:|
| `Trans.Dict.dict` (現行) | 0 | 0 | 0 |
| 候補 | **101** | 0 | 0 |
| 対照 (定数写像) | 3193 | 5096028 | 5096028 |

**候補は 3193 項のうち 101 項で像が $`\mathfrak{T}(M)`$ の外へ出る。** 順序と単射性は
現行と同じく完全なので、争点はそこではなく**記法から出るかどうか**だった。
資料との一致だけを見ていると、この故障は見えない。

最小の反例はサイズ 5 で、すぐ確かめられる:

```
入力  D_0(D_3(D_1(D_3(0))))
候補  psi_(Z 0)(phi(phi(0,0), Z(phi(0,0)) + psi_(Z(phi(0,0)))(Z(phi(0,0)+phi(0,0)))))   inT = false
現行  psi_(Z 0)(phi(0, Z(phi(0,0)+phi(0,0)) + psi_(Z(phi(0,0)))(Z(phi(0,0)+phi(0,0)))))  inT = true
```

内訳: サイズ別 5→1, 6→14, 7→86。入力の先頭添字別 0→56, 1→15, 2→15, 3→15。
像の最外構成子別 psi→57, phi→44。**先頭添字 1,2,3 がきれいに 15 ずつ**なので、
高添字の扱いに系統的な取りこぼしがある。

**対照の教訓。** 最初に置いた対照は「定数 `TM.Term.zero` 写像の inT 違反数」で、
これは 0 を返した — `zero` はそもそも `inT` を満たすからである。**壊れた写像でも
0 になる対照は対照ではない。** 効いたのは `inT` を満たさない項を返す写像を使った方
(3193 件で発火) だけだった。数えるものによって、対照の作り方は変わる。
