# W. plan/README.md の書き方

## W1. 注意力を要求しない

**[plan/README.md](README.md) は、注意して読まなくても間違えない形で書く。**
上から順に実行できる手順、名前と型が書いてある表、走らせるコマンド。
「気をつけること」に頼る記述は、守られなかったときに文書の側が悪い。

## W2. 教訓を書かない。検査に変える

同じ失敗が起きたなら、書くべきものは文章ではない。

| 起きたこと | 書くもの |
|---|---|
| 誤った値が表に載った | ビルドを割る `#guard` |
| 印を手で書いてしまった | 印を計算で出す仕組み |
| 手順を飛ばした | 飛ばすと落ちるゲート |
| 名前が実体とずれた | 名前を探して見つからなければ印が消える仕組み |

**検査にできないものだけを文章にする。** そして短く書く。

## W3. 失敗の回数を数えない

「5 回同じ失敗をした」と書いてある文書は、5 回目の失敗を止められなかった文書である。
回数は改善の証拠ではなく、改善していない証拠である。
数える代わりに [W2](#w2-教訓を書かない検査に変える) を行う。

過去に何が起きたかの記録は [plan/README-old.md](README-old.md) に置いてある。
そこから引っぱるのは、**今の手順を変えるとき**だけでよい。

## W4. 1 つのことは 1 か所に書く

同じことが 2 か所にあれば、片方は必ず古くなる。
2 か所に書きたくなったら、それはもっと抽象的な 1 つの規則か、
手順の 1 ステップに落ちる。

| 書くこと | 場所 |
|---|---|
| 表が何を主張しているか | [table/table-r1.md](../table/table-r1.md) |
| 表に何を載せるか | [plan/spec.md](spec.md) |
| どう作業するか | [plan/README.md](README.md) |
| 何を証拠と呼ぶか | この文書 |
| その行に固有のこと | 行の `note`、または Lean のコメント |

## W5. 抽象的な考察を毎回させない

作業の途中で「どちらが正しいか」を考えさせる文書は、毎回違う答えを生む。
決まっていることは決まった形で書く — 名前、型、通すべきテスト、走らせるコマンド。

## W6. 公開文書にローカルのパスを書かない

[README.md](../README.md)、[plan/](.)、[table/](../table/)、
[rathjen-ordinals.md](../rathjen-ordinals.md) は公開される。
資料は書誌情報と公開 URL で示す。
ローカルに落としてある場所は `.claude/skills/bms-rathjen-lean/` に書く。

## W7. 生成物を手で直さない

`table/` は `lake exe gentable` の生成物である。直すのは `lean/Rows/TM.lean`。

# C. 何を証拠と呼んでよいか

## C1. 同じ写像で両辺を計算した一致は、検査ではない

$`o(M) = t`$ を、$`t`$ を $`o`$ で作ってから確かめても何も分からない。
較正の誤りはこの形で 51 行全部をすり抜けた。
**独立に作られたものと突き合わせて初めて検査になる。**

## C2. 性質をいくつ確かめても、対象は決まらない

$`\varepsilon_1`$ の行で基本列の候補を 3 つ立て、3 つとも「増加・上限未満・共終」を
満たすことを確かめた。正しい列はそのどれでもなかった。
**性質は対象を 1 つに絞らない。** 対象を決めるのは構成である。

## C3. 検査の束が厚いことは、抜けている性質について何も言わない

標準形を問う検査が 1 つも無かったため、非標準の行列が 51 行中 1 行、公開された。
ほかの検査はすべて通っていた。
**「全部ゼロ」は「正しい」ではなく「測っている次元では違反が無い」である。**

## C4. 分母も主張である

「0 件」は母集団しだいで意味が変わる。**母集団の作り方まで書いていない 0 件は、
測定ではない。** 母集団を外部のツールで作ったなら、そのツールにも C5 が要る。

## C5. 検査器は自分の試験を持つ

**両側を見る。** 欠陥を検出できることだけ確かめても、常に赤を返す検査器と区別が
つかない。正常な対照で沈黙することまで見て、初めて検出したと言える。

そして**試験自体も、故意に壊して確かめる。** 「自己試験が通った」は、
その試験を壊してみるまで根拠にならない。

## C6. 読むのではなく、測る

展開がどう動くか、どの補題が要るか、深さがいくつになるか — **予想を書く前に
`#eval` で出す。** 読みで書いた見積もりは繰り返し外れており、測った値は外れていない。

## C7. 外部と食い違ったら、まず自分の翻訳を疑う

外部の実装・表と食い違ったとき、相手が間違っている確率より、
こちらの訳が間違っている確率のほうが高い。
**両辺を正規化してから比べる。** 記法の差を食い違いとして報告した例がある。

## C8. 点における検証は API ではない

`#guard` を 174 個並べても定理は 0 個である。
全称量化された主張が要るなら、等式の層をつくるしかない。
**「よく検証されている」と「定理がある」は別のことである。**
