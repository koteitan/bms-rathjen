# table/ の仕様

[table/table-r1.md](../table/table-r1.md) が何を載せ、何を載せないかを決める文書。
この仕様に合わない変更は入れない。表そのものは生成物なので、直すのは
[lean/Rows/TM.lean](../lean/Rows/TM.lean) の `genTable` である。

## 想定読者

2 種類だけを想定する。

1. 証明の仕方には興味がないが、**対応の結果**を知りたい人
2. この表の **✅ が何を証明したのか**を知りたい人

どちらでもない話 — なぜその設計にしたか、何に失敗したか、どう作業するか — は
table/ に書かない。[plan/README.md](README.md) と
[plan/constitutions.md](constitutions.md) が行き先である。

## 対応表の列

6 列。増やさない。

| 列 | 中身 | 出どころ |
|---|---|---|
| BMS | 行列 | `Row.m` |
| $`\mathfrak{T}(M)`$ | Rathjen R1 の項 | `Row.t` |
| Buchholz | Buchholz $`\mathrm{OT}_B`$ での値 | 下記 |
| 通称 | 同じ順序数の通り名 | `Row.name` |
| 証明 | ✅ か空欄 | 証明書レジストリ |

| 備考 | その行に固有のこと | `Row.note` |

### Buchholz 列

**全行、変換写像 (pss2bp) の出力そのもの**を MathJax の $`\psi`$ 形で書く。
例: $`\psi_{0}(\psi_{2}(0))`$、$`\psi_{0}(\psi_{1}(0))`$ ($`= \varepsilon_0`$)。

変換写像の出力は `oR` の $`1 + \cdot`$ 補正より前の項である。この補正は約束の違いで
あって誤差ではない — pss の対列は空にならず p 進大好き bot の `Trans` は
$`\mathrm{Trans}((0,0)) = 0`$ から数え始めるが、このリポジトリは**空行列**を $`0`$ と
読む。両者は有限の値でちょうど 1 だけずれ、$`\omega`$ 以上では
$`1 + \alpha = \alpha`$ なので全く違わない。列を書くときに $`1 + \cdot`$ を
Buchholz 側で当てるので、Buchholz 列は同じ行の $`\mathfrak{T}(M)`$ 列と全域で一致する。

2026-08-14 から 2026-08-17 まではこの列が $`\psi_0(\Omega_2)`$ 未満で通称を兼ねていた。
いまは通称は**右隣の独立した列**である。空行列だけは変換写像の定義域の外なので、
そこだけ Buchholz 列にも通称 ($`0`$) が出る。

### 通称列

同じ順序数の**通り名**。$`\varepsilon_\alpha`$・$`\zeta_\alpha`$・$`\Gamma_\alpha`$・
$`\omega^\alpha`$ を使う。出どころは `Row.name` で、これは手で書く唯一の表示欄である
($`\mathfrak{T}(M)`$ 列の $`\bar{\varphi}`$ は不動点を飛ばす版なので、通り名は
機械的な書き換えでは出ない — 例えば $`\bar{\varphi}(0,\varepsilon_0)`$ の通り名は
$`\omega^{\varepsilon_0}`$ ではなく $`\omega^{\varepsilon_0+1}`$ である)。
通り名が無い順序数はそこだけ $`\bar{\varphi}`$ のままにする。

### 証明列

**✅ か空欄の 2 値**。「もう少しで ✅」を表す印をここに置かない。
✅ の意味は table-r1.md の [E.cert](../table/table-r1.md#ecert) 1 つに固定する。

### その他の弱いエビデンス列

✅ の**材料**を置く。$`f_n`$、`o`、`bisim6`、`checkAll`。
`oR` は置かない — 表の $`\mathfrak{T}(M)`$ 列そのものが `oR` の出力なので、
同じものを証拠として並べても情報が増えない。

### 備考列

**その行に固有のことだけ**。長い説明、教訓、設計判断は書かない。
複数行に同じことを書きたくなったら、それは備考ではなく仕様か原則である。

## 印は計算する。書かない

✅ も $`f_n`$ も**ビルドが計算して付ける**。

- ✅ — `Evidence.Cert.certRows` に登録された行にだけ付く。登録には
  `Certified(S, t)` の導出が要り、一覧だけ伸ばすとビルドが落ちる
- $`f_n`$ — 行が持つ名前空間の名前を証明ファイルから探して、見つかった行にリンクする。
  名前空間を消すか改名すると印も消える

したがって**手で書いた印は存在しえない**。これは v0.1.41 の較正事故
([plan/constitutions.md](constitutions.md)) の再発防止であり、仕様である。

## 証明の仕様の書き方

「何が証明できると ✅ が付くのか」を**数式の命題**で書く。散文で言い換えない。

- 命題は `E.<記号>` を章名にする
- 定義は `D.<記号>`。新しい記号を導入するときに使う。
  帰納的な定義の規則は `D.<記号>.<規則名>` (例: `D.Certified.lim`)
- 定理・補題は `T.<記号>`。読みやすさのため、または複数箇所から引くために使う
- **トップダウンに書く** ([plan/constitutions.md](constitutions.md) W8)。
  主張が先、定義は後。`# 定義` の章の中も粗いものから細かいものへ
- 使う記号には必ず定義がある。数式に出したものは `# 定義` に載っていること。
  「項」「行列」「述語」のような日本語も記号である — 集合として定義する

章名に絵文字・ダッシュ・記号を入れない。リンクのアンカーが壊れる。

## 数式の書き方

GitHub の MathJax で描画されることが条件である。ローカルで描けても意味がない。

- 別行立て — ` ```math ` フェンス。ドル 2 つで挟む書き方は使わない
- 行内 — `` $`…`$ ``。ドル 1 つで挟む書き方は使わない
- 改行 — `\cr`。バックスラッシュ 2 つは GitHub の変換で壊れる
- 行内数式の不等号 — `\lt` / `\gt`
- ドル記号を数式の中に書かない (`\text{…}` の中も含む)
- 絵文字を数式の中に書かない。KaTeX が字形を持たない
- 関数適用は $`A(b, c)`$ と書く。**並置 $`A\ b\ c`$ は使わない** — 引数が
  いくつあるのか読めない。Lean のコードをそのまま引用する箇所だけが例外である

`node scripts/check-math.js <file>` が 0 errors であることを確認する。

## table-r1.md に書かないもの

読み手が表を読むのに要らないものは [table/misc.md](../table/misc.md) へ送る。
今そこにあるのは $`\mathrm{RawCertified}`$、$`f_n`$ 印の中身、
E.cert が言っていないこと、T.unique / T.bound / T.eps0、
規則の閉包 $`\mathrm{Cl}(R)`$ の定義と性質である。

**設計・失敗・作業の話は table/ に入れない** (この文書の冒頭)。
たとえば「レジストリに登録しないと ✅ が付かない」は作業の話なので、
この文書の[印は計算する。書かない](#印は計算する書かない)にだけ書く。

## どこを直すと table-r1.md が変わるか

`table/table-r1.md` は `lake exe gentable` の生成物である。**直接編集しない。**

| 直したいもの | 直す場所 | 要る手順 |
|---|---|---|
| 表の行 (行列・値・備考) | `lean/Rows/TM.lean` の `rows` | `lake build` してから `gentable` |
| 表より上の本文・バージョン | `lean/Rows/head.md` | `gentable` だけ |
| 表より下の本文 | `lean/Rows/tail.md` | `gentable` だけ |
| 列の作り方・印の付け方 | `lean/Rows/TM.lean` の `genTable` | `lake build` してから `gentable` |

```sh
cd lean && lake exe gentable > ../table/table-r1.md
```

本文は**素の Markdown** である。バックスラッシュを 2 つ書く必要は無い。
置換も無い — `head.md` の中身がそのまま出る。

**バージョンも `head.md` に直接書いてある。** 上げるのに `lake build` は要らない。

`table/diff.md` と `table/misc.md` は生成物ではない。手で書く。
