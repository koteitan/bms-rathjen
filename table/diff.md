このリポジトリの `Trans.oR` と、Hexirp 氏の「バシク行列システム４と全部盛りオクフ・ベータの
対応」を突き合わせた記録。**11 行が食い違う。2 行は先方の表自身が誤りを示し、8 行 (族 1、族 2 の
2 行、族 3 の 3 行、族 4 の 327 と 328 行目) は証明で決着した。残る 1 行 (族 4 の 326) は未決**で、

**行き先は Rathjen の $`\mathfrak{T}(M)`$ ではなく「全部盛り」の OCF である**が、
**Rathjen 由来の部分では Rathjen と一致するはず**、と著者が述べている。だから重なる範囲での
食い違いは系の違いではなく本物の食い違いである。`W(x)` が訳せないのはその重なりの外で、
突き合わせているのは両者が重なる Veblen 断片に限られる。

再現手順は `scripts/hexirp-rathjen-check.py` の冒頭にある。

## 記法

以下、**先方の記法をそのまま使う**。先方と当方の対応は

```
先方 phi(a,b)  =  当方 phiNF (1+a) b
先方 w(x)      =  当方 phiNF 0 (1+x)          w(0) = ω
先方 W(0)      =  当方 Z 0 = Ω
先方 W(x), x≠0 =  訳せない (下記)
```

`phiNF` であって `phi` ではない。当方の φ̄ は [Rathjen, 1991] 2.6(vi) の「不動点を数え直す」版で
不動点を飛ばし、先方の φ は飛ばさない。先方の `phi(0,e(0)+1)` と当方の φ̄(0,ε₀) は同じ
ものである。生の φ̄ で組むと記法の差が全部「食い違い」に化ける。

行番号は先方の表の高さ 2 の部分を上から 0 起点で数えたもの。

## 決めた道具

一致率では勝敗が決まらないので、**BMS の順序で並べ直し、隣接対の狭義単調性を両側に当てる**。
正しい BMS → 順序数 の写像は単調な単射だから、自分の順序と矛盾する側が誤りである。隣接対で
足りるのは 𝔗(M) の順序が推移的だからである。

```
単調でない対        先方 2        oR 0
潰す対              先方 2        oR 0
相異なる値          先方 388/390  oR 390/390
対照 (逆向きに見る) 389/389 が壊れる  = 試験は生きている
```

`NfOK` は使わない。あれは基本列の組み立て定理の側条件であって Rathjen 表記の標準形の述語ではない。

先方の記法への逆訳も検算してある: 390 行を逆訳して先方の構文解析器に通し直し、
**もとの項に 390/390、oR の値に 390/390 が戻る**。対照として二つの列を入れ違えると
379/390 になり、これは一致している行数と一致する。よって以下の綴りは信用してよい。

未決のものは双方とも単調かつ単射で、内部整合性も一致率もこれ以上は分けない。
「〜に見える」は読みであって証拠ではない。

以下 **E3** と呼ぶのは、行ごとの添字 k を固定した上での

```

定理**であって、有限個の照合ではない。対応表ではこれを $`f_n`$ 印で表している
([table-r1.md](misc.md#efs))。

## 決められなかった理由と、証明が示すべきこと

BMS 側の力学で当てる試験も書いた。行列 M の展開 M[n] の像が、正しい値の基本列の第 n 項に
なっているかを見るものである。結果は 9 行すべてで **0/0** — 先方の値にも当方の値にも当たら
なかった。これは **E3 の添字が行ごとに違う** (`fsN` に一律のずらしを当ててはならない) という
既知の事実の現れであって、どちらかの証拠ではない。

したがって決着には、行ごとの添字を固定した上で

```
oR(M[n]) = fsN(oR(M), n)
```

を該当行について示す必要がある。これが上の E3 である。
食い違う 9 行はすべて Veblen 断片にあるので、ψ・Z の領域には立ち入らない。

## `oR` 側で分かったこと (2026-08-14)

未決 3 行を含む「`oR` が要る 12 行」に取り掛かって、証明の前に測定で出たことを書いておく。

**残り 12 行のうち、展開が `fsN` に一様なずらしで乗るのは 6 行だけだった。** 残る 6 行は
ずらしを 12 まで広げても、1 始まりにしても乗らない。展開の値が `fsN(t, ·)` の 0〜30 項の
どこにも現れない。

**これは表の値が誤りという意味ではない。** 対応表の ✅ が要求するのは、展開の値の列
$`f_n`$ が単調・有界・共終であることで、**$`f_n`$ が標準基本列であることは要求していない**
([table-r1.md](table-r1.md#dcertifiedlim))。実際、乗らない 6 行にも閉じた形は
あった:

```

(0,0)(1,1)(2,2)(2,2)              n≥1 で ψ_{Z0}(ZΩ + 塔)、底は φ̄(1,Ω) の 2 倍
```

**塔の底が「2 倍」なのが 6 行中 4 行に共通**で、これは BMS の展開が最後のブロックを 2 つ
置くことの像である。`fsN` が外れるのは、`fsN` が不動点飛ばしの規則から底を「+1」側に
取るためで、BMS は「2 倍」側を出す。どちらを `f` に渡すべきかは決まっていて、**行列が
選ぶ方**、つまり測定した側である。

これらは測定であって定理ではない。定理にするには `oR` の側で $`n`$ を量化する必要があり、
それが下の 2 の作業である。

### 読み手の側で証明できたこと

`oR` は「点での検証はあるが等式の層が無い」計算だった (`lean/Evidence/Cert.lean` §21.2)。
そこに層を作る作業を、`(0,0)(1,1)(2,1)(3,0)` の 1 行で進めている。鎖は 3 本のリンクに
分かれ、**そのうち 2 本と、残る 1 本の前半が定理になった**。

```
展開 --ofMatrix--> 梯子 --transPort--> BT --dict--> 値
        リンク 1 ✅      リンク 2 ✅          リンク 3 ✅
```

**3 本とも定理になり、`(0,0)(1,1)(2,1)(3,0)` の行は `oR` の側で全 n について決まった**
(`Rows.Selected.G1.oR_MG`)。`oR` を $`n`$ で量化した主張が定理になるのは
`Evidence/Cert.lean` §21.8 の rung 族に続いて 2 例目で、**対応表の行としては初めて**である。

### `CaseThree` は閉じた — 順序の話ではなく長さの話だった (2026-08-16)

```

c ≤ b                  102 中 66 で偽
W ≤ psi_0(c の頭)      66 中 24 で偽   (明らかな修理。これも落ちる)
```

通ったのは**長さ**である。まず `c` と `b` を比べる。`c < b` と `c = b` は即座に済む。
`c > b` が中身のある場合で、そこでは不動点条件 `c < b ⊕ psi_0(c)` が

`c` の尾 `W` 対 `fsP c n` になる。ここで新しい 3 つの事実が効く。

```

fsP c 0 は c より短くない                             len_fsP_zero
n を上げるのは右に足すだけ                            mat_fsP_mono
```

`W` は `c` の尾なので `|W| ≤ |c| ≤ |fsP c 0|`。そして
**`Y ++ Z` 未満で `Y` より長くない行列は `Y` 以下である** (`cmpM_le_of_len`、
既にあった `cmpM_gt_lt_len` の対偶)。これで閉じる。

### `plus` の結合律が入り、`Hlim` が 2 つに割れた (2026-08-16)

**最初の障害だった `plus` の結合律は片付いた** (`Evidence/CNVOps.lean` §19)。これは
形式的な等式ではない。`plus` は [Rathjen, 1991] 2.6(ii) — 「β の頭より小さい α の成分を

無ければ**偽**である。証明は `c1 ≤ b1` かどうかで 2 つに割れる。

```

c1 > b1   内のふるいは見えない。c1 以上のものはもともと b1 以上
```

これで `sumVal (app r s) = sumVal r ⊕ sumVal s` が言える。`fs` は最後の加数にしか
作用しないので、展開の値は**触っていない前置き ⊕ 列の第 n 項**である。よって `Hlim` は
`Hclosed` と同じ継ぎ目で 2 つに割れる (`hlim_supply`、証明済み)。

```

            lim_clauses_phi_arg / lim_clauses_fsGen はまさにその 3 つに向けてある

### `PrefixLim` も閉じた — 順序を成分列で読む層を足した (2026-08-16)

`plus` は成分列の操作なので、項の順序を**成分列の辞書式順序として読む層**を作った
(`Evidence/CNVOps.lean` §20)。`TM/Order.lean` は `add` 構成子ごしに比べる 3 つの事実

なので、この 3 つが 1 本の等式に組み上がる。

```
lt s t  =  ltL (toList s) (toList t)
```

この層の上で `plus` の 2 つの単調性 (§21) と共終性 (§23) が出る。共終性は

### 近道は間違いだった (2026-08-17)

ある — 当リポジトリ自身の naruyoko pss2bp 移植 (`oRB`)、Hexirp の公開解析、そして

**何が壊れて何が壊れないか。** `B` が Buchholz の符号化だとは一度も主張していない。

### 引数には引数の値付けが要る (§17)

§16 の除外は**入力が間違っていた**。`RegionV` はその区別を最初から持っている:
`sumVal` は最上位の和として読んだ値、`argVal` は同じ添字を**引数**として読んだ値で、
両者は違う (あちらでは `Ω` の並びを `ε` に読み替える)。§14-§16 は `collapse` に
和の値付けを食わせていた。

引数の値付け (`ψ₀(a)` の行列を訳して外側を剥がす) に替えると、再帰

```

```

は **847 個中 696 個**で成り立つ (和の値付けでは 618)。ずれ方も予想どおり:

```

y1(y2(0))   argV Ω₂    sumV ε_Ω
```

**読み方の規則 (鎖の場合、測定)。** 最上位の `ψ₀` の下の鎖の段を `v₁, v₂, ...` として

```

残った節の添字は、そこまでに現れた相異なる段の中での順位 (最上位を 0 位とする)
```

```
(0,0)(1,2)             ψ₀(ψ₁(0))       段 {0,2}: 2 の順位は 1
(0,0)(1,1)(2,2)        ψ₀(ψ₂(0))       1 < 2 なので ψ₁ の節は落ちる。2 の順位は 2
(0,0)(1,1)(2,2)(3,3)   ψ₀(ψ₃(0))       2 つ落ちる
(0,0)(1,1)(2,2)(3,1)   ψ₀(ψ₂(ψ₁(0)))   最後の節は残り、順位 1
(0,0)(1,2)(2,2)        ψ₀(ψ₁(ψ₁(0)))   2 は 2 より小さくないので両方残る。どちらも順位 1
```

§15 の `encB` が食い違うのはこれが理由で、食い違いが `(0,0)(1,1)(2,2)` から始まるのも
それが**鎖の段が真に増える最小の行列**だからである。

### 和の側 — 族を測った (§17.2)

鎖の規則は和に届かない。族で測ると:

```

y0(y1(y2(0)+y2(0)))        y0(y2(0)+y2(0))                  節が**消える**
y0(y1(y2(0)+y1(0)))        y0(y2(0)+y1(y2(0)+y1(0)))        **持ち上がって、中にも残る**

**決まっていないこと。** 最上位の `ψ₀` は持ち上げない (最終行) — 加数はすべて自分の段より
上なのに、である。だから「自分より上を持ち上げる」という単純な規則ではない。

### 決断は 1 — 移植する。範囲は測ってあり、雛形は repo にある (§18、2026-08-17)

閉じた形を探す道が収束しない理由は構造的である。`Mark` は**状態**であって、`Trans M`
単体は合成的にならない。合成的なのは組 `(Trans M, Mark M ·)` の方で、§17.2 の

**移植は算法より小さい。** 領域の 380 個の添字と、再帰が訪れる相異なる接頭辞 714 個で:

    2       型  0 (Trans (Pred M) = 0)

`red` は `Trans/Recal.lean` の最大の関数だが、この領域では死んだ枝である。残る 2 つの
構造的な枝には `B` 側の記述があり、**どちらも定理になった**:

```

1 つ目: `fpar0` は `j-1` から左へ走査して最初に現れる真に浅い列を返し、
`BMS.parent M 0 j` は同じ集合の最大元を取るので、どの行列でも一致する。したがって
`Evidence/Region.lean` の親の道具と §8 の「行 0 の親鎖 = 左極小」がそのまま
アルゴリズムに効く。`fpar` は `isParentP`・`isAnc`・`fAnc`・`ppair`・`isUnadmitted`・
`trMax` と型 1〜6 のすべてに現れる。

2 つ目はその上に乗る: `ppairAux` は最後の列から左へ歩き、`fAnc` の終点をブロックの根と
して切り出す。`fAnc` は行 0 の親鎖そのもの (`fAnc_eq`)、鎖は左極小 (§8)、そして `matB`
では加数の内側から届く左極小はその加数自身の根である — 根は深さ 0 で、加数の中でその後に
続く列はすべてより深いからである。

### 標準形が見つかった (§19、2026-08-17)

移植の門は「`matB` の行列では `red` が走らない」ではなかった。節が 4 個以下・段が 3 未満の

標準形で、それはこれである:

```

            (最上位の節には親が無いので段は 0)
```

**測定は近似ではなく一致である**。3 つの全数列挙のどれでも

```
段 < 3、節 ≤ 4      220 個     220 / 220 一致  (既約は 101)
段 < 4、節 ≤ 5     5101 個    5101 / 5101 一致 (既約は 697)
段 < 3、節 ≤ 6    16332 個   16332 / 16332 一致
```
