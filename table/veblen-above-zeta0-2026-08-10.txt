== 帰結: 新しいテンプレートは 1 つだけ ==

4 行のうち 2 行は、既存テンプレート (B)/(C) の第 1 引数を 1 から 2 に替えただけである。
これらのテンプレートは既に第 1 引数を引数として取っているので、追加作業は
側条件の放電のみと見込まれる。

残る 2 行が要求するのは、(C) の**鏡像**である:

```
(C)  fs n = φ̄ a (g n)        第 2 引数に内側の列を入れる   — 証明済み
(C') fs n = φ̄ (g n) b        第 1 引数に内側の列を入れる   — 未着手
```

φ̄(ω,0) では g = ofNat(n+2)、φ̄(ε₀,0) では g = tower(n+1)。
どちらも内側の列は既にファイルにある (`ofNat`, §9 の `tower`)。

  第 1 引数を動かす場合にどれが効くかは (C) の場合と異なる可能性がある。
* この 4 行の**中間値**は測っていない。行の列だけである。

== 追記 (2026-08-10): 1 番目が解決した。答えは「閉じない」 ==

上の 4 行の項と列は veblen2 が独立に再測定し、4/4 一致した (n ≤ 5..6)。
その上で、私が書かなかった陰性対照が走り、**(C') は一般には偽**であることが判明した。

  (C') fs n = φ̄ (g n) b     は **b = 0 でなければ成り立たない。**

理由は標本の不足ではなく構造的である。g n < a なるすべての n について
φ̄(a,0) は φ̄(g n, ·) の不動点なので、b < φ̄(a,0) であるかぎり

        φ̄(g n, b)  <  φ̄(a, 0)   (すべての n について)

が成り立つ。つまり**列全体が φ̄(a,0) という一つの上界で頭打ちになる**。
b > 0 ならその上界は目標 φ̄(a,b) より真に下にあるので、列は共終になり得ない。
g をどう取り替えても直らない、という点が重要である。

実測 (coordinator, 独立):
    lt (φ̄(ω,0)) (φ̄(ω,1))              = true    目標の下に φ̄(ω,0) がある
    lt (φ̄(k+2,1)) (φ̄(ω,0))            = true    k ≤ 7 のすべてで、列は φ̄(ω,0) より下
veblen2 の測定 (k ≤ 13、b = ζ₀ でも同様) と一致する。

b = 0 ではこの副節が空虚になり、共終性は閉じる (φ̄(ω,0) の下の CNV 項 33 個、
φ̄(ε₀,0) の下の 39 個、取りこぼし 0)。さらに (C) が必要とする `hside` は
**消える** — 2.3.13(iii) が s ≤ b を返すが、b = 0 なら s = 0 で自明に閉じる。
したがって (C') は (C) より**簡単**である。ただし制限つきの主張としてのみ。

上の 4 行はいずれも b = 0 なので、この制限はここでは何も損なわない。
だが保守的な仮定ではなく**真の制限**なので、反例とともに文に書く。

== 追記 (2026-08-10): ω 例外の原因が判明した。添字のずれである ==

「β = ω のときだけ ε 系の定理が外れる」という文書化済みの例外は、順序数論的な
機微ではなく `fsC` の添字規約である。実測 (coordinator, 独立):

    fsC ω n = ofNat (n+1)        n ≤ 5 で真、  fsC ω n = ofNat n は n ≤ 5 で偽
    φ̄(1, fsC ω n) = ε_{n+1}      行 ε_ω の第 n 展開は ε_n

帰結が 3 つある。

1. **原因は a に依存しない。** veblen2 が a = 2 (ζ_ω) で同じ外れを観測したのは
   一般則の一例である。規則は「φ̄(a,ω) 行で外れる」ではなく
   「**`fsC` の ω での値が 1 始まりで、行列の展開は 0 始まりである**」と、
   原因の側で述べるべきである。
2. **φ̄(a,ω) 行に限らない。** 内側の列が ω に到達する行はすべて継承する。
3. **例外を消せる。** `fsC_omega : fsC ω n = ofNat (n+1)` を 1 行の定理として
   置けば、β = ω は「避ける対象」ではなく「ずらして代入する対象」になる。
   `fsC` 自体は変更しない — §15.15 の 2 定理は現規約で 129/129 較正済みであり、
   規約を動かせばそれが全部無効になる。

なお φ̄(ε₀,0) の列が tower(n+1) であって tower n でないのは、`tower` の
0 番目の値をどこに置いたかという**別の**規約選択である。同じ「+1」に見えるが、
同一の原因だと述べる根拠は測っていない。
